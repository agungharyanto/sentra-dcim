## Uji rollback v0.1.4 → v0.1.3 → kembali

Log: [`v0.1.9-rollback.txt`](v0.1.9-rollback.txt).

| Langkah | Perintah | Durasi | Hasil |
|---|---|---|---|
| Rollback | `ops/rollback.sh v0.1.3 --yes` | 16 dtk | Backup otomatis → skema 2 → 1 (tabel `ops_runs` di-drop) → checkout `v0.1.3` → `/version` = v0.1.3, API test 23/23 |
| Roll-forward | `git checkout main && ops/rollback.sh main --yes` | 15 dtk | Backup otomatis → checkout `main` → `migrate up` skema 1 → 2 → `/version` = v0.1.4, API test 23/23, git bersih |

Temuan & perbaikan: label "from" di log roll-forward tertulis `v0.1.4 (schema 1)` karena dibaca dari git
setelah checkout manual. Diperbaiki di v0.1.9: versi asal kini dibaca dari `/api/v1/version` yang sedang berjalan.

Catatan: data di tabel yang di-drop oleh migrasi `down` (di sini `ops_runs`) hilang setelah rollback —
tetap tersedia di backup yang diambil otomatis di awal rollback.

```
0.0.0.0:49194   sshd

127.0.0.1:5432  docker-proxy   (PostgreSQL)

127.0.0.53:53   systemd-resolved
```

**Uji dari luar (jalankan dari komputer lain, bukan dari server):**

```bash
# 1. Scan port TCP umum + port aplikasi — harapan: hanya 49194/tcp open, sisanya filtered
nmap -Pn -sS -p 22,80,443,2019,5432,6379,8080,49194 <IP_SERVER>
# 2. Scan seluruh port TCP (lebih lama) — harapan: hanya 49194/tcp open
nmap -Pn -sS -p- --min-rate 1000 <IP_SERVER>
# 3. Sampel UDP — harapan: open|filtered / filtered, tidak ada yang open
sudo nmap -Pn -sU --top-ports 50 <IP_SERVER>
```

Hasil uji dari luar: **menunggu dijalankan oleh pemilik proyek** (ISS-005).
